# Manner_Web 权限系统重构方案（方案 C）

> 状态：已确认，开始实施（分支 `dev`）。
> 决策：RBAC + 数据范围 + 部门角色继承（方案 C）；彻底移除员工级直接授权；perm_version 失效检测即时生效；首版支持父子角色（角色继承）。
> 相关文档：[权限系统设计.md](./权限系统设计.md) · [数据库设计.md](./数据库设计.md) · [API文档.md](./API文档.md)。

## 一、目标模型

**最终权限 = Σ（员工角色 + 部门角色）展开后的有效角色权限**

```
employee 分配角色(employee_roles) ─┐
department 绑定角色(department_roles) ──► roles(含 parent_id 角色继承链) ──► role_permissions ──► permissions
```

- 权限继承：子角色沿 `parent_id` 继承祖先全部权限；子角色数据范围不得大于父角色范围。
- 数据范围 `scope_type`（角色级）：`all / subtree / department / self / custom`
  - `all`：全部数据
  - `subtree`：本人归属部门 ∪ 各部门子树（含子部门）
  - `department`：与本人共享任一部门的所有员工
  - `self`：仅本人
  - `custom`：`role_department_scopes` 指定的部门集合
- 多来源并集：任一来源为 `all` 则该数据权限不过滤；否则各来源可见集合并集。
- 数据范围仅作用于**数据型权限**（`employee:list/view/view_sensitive`、`chat:employees`）；功能型权限只做码级校验。

## 二、数据库变更

新表（`CREATE TABLE IF NOT EXISTS`）：
- `roles`：`id CHAR(36) PK`、`name UNIQUE`、`code UNIQUE`、`parent_id`（继承）、`is_system`、`scope_type VARCHAR(16)`、`description`、时间戳
- `role_permissions`（role_id ↔ permission_id，双 FK 级联）
- `employee_roles`（employee_id ↔ role_id，双 FK 级联）
- `department_roles`（department_id ↔ role_id，双 FK 级联）
- `role_department_scopes`（role_id ↔ department_id，仅 scope_type=custom）

employees 追加 `perm_version INT DEFAULT 0`。

种子与清理：
- 种子 `super_admin` 角色（is_system=1、scope_type=all、全量权限）。
- `DROP TABLE IF EXISTS employee_permissions;`（彻底移除直授）。
- 存量迁移：持全部权限的员工绑定 `super_admin`；其余按各自权限集生成私有角色（role id 取员工 id）绑定本人。
- 首个管理员注册改为绑定 `super_admin` 角色。

## 五、防提权与安全约束

- 分配角色：目标角色权限集 ⊆ 操作者有效权限集，且目标角色范围 ≤ 操作者范围。
- 父子角色：子角色范围不得大于父角色（偏序 all ⊇ subtree ⊇ department ⊇ self；custom 指定部门须 ⊆ 父角色可见部门），沿 parent_id 防环。
- `is_system`（super_admin）不可删除/改名/改权限/改范围；不可移除最后一名持有者。
- 不能修改自己的角色/部门归属。
- 所有变更写审计日志（复用 append_log）。
- perm_version 波及面：角色权限/继承/范围变更、员工角色分配、部门角色绑定、员工部门归属、部门树结构变更均须正确递增。
