# Manner_Web 权限系统设计（方案 C：RBAC + 数据范围 + 部门角色继承）

> 适用范围：开发与维护人员。
> 事实依据：`backend/sql/init.sql`（角色表与权限码种子）、`backend/src/services/permission.rs`（权限解析核心）、`backend/src/handlers/role.rs`（角色管理 API）、`backend/src/middleware/auth.rs`（认证与 perm_version 失效检测）、`backend/src/utils/jwt.rs`（Claims）。以代码为准。
> 方案背景与决策记录见 [权限系统重构方案.md](./权限系统重构方案.md)。

## 1. 权限模型总览

系统采用 **RBAC（角色授权）+ 数据范围 + 部门角色继承** 三层模型，**员工级直接授权已彻底移除**（无 `employee_permissions` 表）：

```
employee 分配角色(employee_roles) ─┐
department 绑定角色(department_roles) ──► roles(含 parent_id 角色继承链) ──► role_permissions ──► permissions
```

- **最终权限 = Σ（员工角色 + 部门角色）沿 `parent_id` 继承链展开后的角色权限并集**。
- **角色继承**：子角色沿 `parent_id` 继承祖先全部权限（每个角色的权限携带该角色自身声明的数据范围）。
- **部门角色**：员工归属某部门后自动获得该部门绑定的角色权限（`department_roles`，仅直接归属，不级联到子部门）。
- **数据范围（scope_type）**：仅作用于**数据型权限**（`employee:list` / `employee:view` / `employee:view_sensitive`、聊天员工名单），功能型权限只做码级校验。
- **令牌快照 + perm_version 即时失效**：access 令牌内嵌签发时的授权快照（`permissions` + `grants` + `perm_version`）。任何权限相关变更（角色权限/继承/范围、员工角色分配、部门角色绑定、部门归属、部门结构）递增受影响员工的 `employees.perm_version`，中间件比对不一致即从库重算有效授权并替换注入——权限变更**即时生效**，无需重登或等待令牌过期。

## 2. 权限码清单（18 个）

种子数据位于 `backend/sql/init.sql`（`INSERT IGNORE INTO permissions`）。按模块分组：

### 2.1 员工模块（employee）

| code | 名称 | 说明 |
| --- | --- | --- |
| employee:list | 查看员工列表 | 员工列表（受数据范围过滤）；权限字典 `GET /api/permissions` 改为要求 `role:manage` |
| employee:view | 查看员工详情 | 单员工详情（受数据范围过滤，不可见返回 404） |
| employee:create | 新增员工 | 创建员工账号 |
| employee:edit | 编辑员工 | 编辑员工资料、调整归属部门 |
| employee:delete | 删除员工 | 删除员工账号 |
| employee:password | 重置员工密码 | 重置他人密码（不可重置自己） |
| employee:view_sensitive | 查看敏感信息 | 解密明文查看（受数据范围过滤，强制审计日志） |

## 3. 首个管理员

首个管理员通过匿名注册创建（`POST /api/auth/register`，仅全新部署且 `employees` 为空时可用）：

- 注册成功后自动绑定内置 `super_admin` 角色（`is_system=1`、`scope_type=all`、全量权限），并将注册开关置 `'0'`。
- 事务内 `SELECT ... FOR UPDATE` 防并发抢注。

## 4. 角色管理 API

### 4.1 角色 CRUD（`role:manage`）

| 端点 | 说明 |
| --- | --- |
| `GET /api/roles` | 角色列表（含权限码、范围、成员数、父角色） |
| `POST /api/roles` | 创建角色（名称/父角色/范围/权限码/指定部门） |
| `PUT /api/roles/:id` | 更新角色；`is_system` 角色仅允许改描述 |
| `DELETE /api/roles/:id` | 删除角色（`is_system` 拒绝、有子角色时拒绝） |
| `PUT /api/employees/:id/roles` | 整体替换员工分配的角色 |
| `GET /api/departments/:id/roles` | 部门绑定的角色列表 |
| `PUT /api/departments/:id/roles` | 整体替换部门绑定的角色（super_admin 不允许经部门绑定） |

### 4.2 防提权与保护规则

| 规则 | 说明 |
| --- | --- |
| 码级子集 | 操作者只能分配/创建「权限集 ⊆ 自己有效权限」的角色（目标角色含父角色继承后的全部权限） |
| 范围约束 | 数据型权限上，目标角色范围不得超过操作者自身范围（偏序 `all ⊇ subtree ⊇ department ⊇ self`；`custom` 须被操作者 custom 集合覆盖） |
| 父子范围 | 子角色范围不得大于父角色；沿 `parent_id` 防环（`would_create_cycle`） |
| super_admin 保护 | 不可删除/改名/改权限/改范围；不可经部门角色绑定；不可移除最后一名持有者 |
| 不能改自己 | 员工角色分配拒绝操作者本人（`id == auth.id` → 400） |

### 4.3 即时生效

上述任意变更都会递增受影响员工的 `employees.perm_version`（角色变更波及直接/经部门持有者及经继承持有者；部门结构/归属变更波及相应员工），令牌在下次请求即自动重算，**无需重登**。

## 5. 数据范围（scope_type）

| 值 | 语义 | 可见性 |
| --- | --- | --- |
| all | 全部数据 | 不过滤 |
| subtree | 本部门及子部门 | 员工归属部门 ∈ {本人部门 ∪ 各部门子树（递归后代）} |
| department | 本部门 | 员工与本人共享任一部门 |
| self | 仅本人 | 仅本人 |
| custom | 指定部门 | 员工归属部门 ∈ `role_department_scopes` 指定集合 |

- 多来源并集：同一权限码来自多个角色时各范围取并集；任一来源为 `all` 则全可见。
- 应用点：`GET /api/employees`（列表过滤）、`GET /api/employees/:id`、`view_sensitive`（不可见按 404 处理，防探测）、`GET /api/chat/employees`（持有 `employee:view` 的用户按该权限范围过滤，否则全量）。
- 实现：`services/permission.rs` 的 `build_scope` / `apply_scope_filter` / `is_visible` / `scope_contains` / `scope_covers`（`WITH RECURSIVE` 展开部门子树）。

## 6. 权限校验机制

- **认证中间件**（`middleware/auth.rs`）：验签 → `typ=access` → 黑名单 → CSRF（Cookie+写方法）→ `pwd_version` / `status` / `active_session` 校验 → **perm_version 失效检测**（不一致即 `resolve_effective_grants` 重算并替换注入的 `AuthUser`）。
- **`require_permission(&auth.permissions, code)`**：比对有效权限码集合，不含则 403（code=40004）。`auth.permissions` 已由中间件保证为最新。
- **数据型接口**再叠加 `build_scope` + `apply_scope_filter` / `is_visible` 做行级过滤。
- **令牌失效语义**：`pwd_version` 改密全端失效；`status != 1` 立即失效；`perm_version` 权限变更即时重算；`active_session` 单设备登录踢下线（40010）。

## 7. 安全要点小结

| 要点 | 说明 |
| --- | --- |
| RBAC + 数据范围 | 权限经角色授予，数据范围控制"能看哪些人" |
| 防提权链 | 码级子集 + 范围偏序 + 父子范围约束 + 防环 |
| super_admin 兜底 | 内置不可改、不可删、不可经部门绑定、至少保留一名 |
| perm_version 即时生效 | 权限变更无需重登/等过期 |
| 数据范围防探测 | 单资源不可见统一 404 |
| 防拉黑保护派生 | `chat:protect_block` 由角色授权派生，无冗余字段 |
| 全变更审计 | 角色/授权/部门绑定等全部写业务日志（含操作者、目标、IP） |
