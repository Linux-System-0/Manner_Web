# Manner_Web 项目说明

## 项目背景与目标

Manner_Web 是一个面向企业内部的 Web 管理系统，将员工管理、权限控制、站内聊天与系统设置整合到同一平台：

- 统一管理员工账号，通过**角色授权**（RBAC + 数据范围 + 部门角色继承）提供可审计的访问控制；
- 提供站内聊天能力，支持单聊与群聊、文本与文件消息、拉黑与防拉黑保护，降低对第三方工具的依赖；
- 关键系统参数（登录页、登录限流、上传限制、注册开关等）可在线配置，无需改代码；
- 访问日志与业务日志可在系统内在线查看。

项目采用前后端分离架构：后端为 Rust 实现的 REST API 服务，前端为 SvelteKit 5 构建的纯 SPA 静态站点。详细设计见[架构设计](架构设计.md)。

## 核心功能

### 员工管理

- 员工信息的增删改查与详情查看；
- 重置员工密码（随机初始密码，首次登录强制改密）；
- 通过**角色**分配员工权限（RBAC + 数据范围 + 部门角色继承，权限变更即时生效）；
- 禁用/启用员工账号（禁用后其令牌立即失效）；
- 防拉黑保护：有效权限含 `chat:protect_block` 的员工禁止被其他账号拉黑；
- 新增员工时自动创建「操作者 ↔ 新员工」的单聊会话。

### 权限与角色

- 角色管理：创建/编辑/删除角色，配置权限码与**数据范围**（全部/本部门及子部门/本部门/仅本人/指定部门）；
- 角色继承：父子角色，子角色继承父角色权限（子范围不得大于父范围）；
- 部门角色绑定：员工归属部门后自动获得该部门绑定角色的权限；
- 内置 `super_admin`：全量权限 + 全部数据，不可删除/修改，至少保留一名。

### 聊天

- 单聊与群聊两种会话类型，群聊支持设置群名、添加/移除成员、调整成员角色、解散群聊；
- 文本与文件消息，消息记录按会话分页获取（单次上限 200 条）；
- 拉黑与防拉黑保护：可拉黑其他员工（保护账号除外），对方被拉黑后无法向你发送消息；
- 聊天文件经 `/api/chat/file/:name` 鉴权下载（仅相关会话成员可访问）。

### 系统设置

- 登录页配置（登录页标题、主题、站点标题）；
- 聊天文件上传限制（禁止 / 无限制 / 数字+单位，如 `10MB`）；
- 登录限流参数（`login_max_failures`、`login_lock_window_secs`，可在线调整并即时生效）；
- 注册开关（控制**首个管理员**注册通道）。

### 日志

- 访问日志（请求方法、路径、状态码、耗时）与业务日志在线查看。

## 技术栈总表

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 后端 | Rust 2021 edition | 服务端语言 |
| 后端 | axum 0.7 | Web 框架（REST API 路由，multipart） |
| 后端 | sqlx 0.8 | 异步数据库访问（MySQL，运行时 SQL） |
| 后端 | jsonwebtoken 9 | JWT 签发与校验（HS256） |
| 后端 | bcrypt 0.16 | 密码哈希（cost 12） |
| 后端 | tokio 1 / tower-http 0.5 | 异步运行时 / 中间件、CORS、静态服务 |
| 后端 | tracing 0.1 + tracing-subscriber | 结构化日志（JSON 滚动日志） |
| 前端 | SvelteKit 5 + Svelte 5 | 应用框架（纯 SPA，runes 语法） |
| 前端 | Vite 8 + TypeScript 5 | 构建工具与类型系统（strict） |
| 前端 | @sveltejs/adapter-static | 静态站点适配器（fallback index.html） |
| 前端 | 自研组件库 | `src/lib/components` 全套自研组件（无 React/antd 运行时依赖） |
| 数据库 | MySQL 8 | utf8mb4 / utf8mb4_unicode_ci / InnoDB |
| 部署 | Nginx | 静态资源托管 + `/api`、`/uploads` 反向代理 |

## 目录结构

```text
Manner_Web/
├── backend/                  # Rust 后端服务
│   ├── src/                  # 源码
│   │   ├── main.rs           # 启动入口
│   │   ├── config.rs         # 环境变量配置
│   │   ├── db.rs             # MySQL 连接池与迁移执行
│   │   ├── error.rs          # 错误类型
│   │   ├── handlers/         # 路由与请求处理（auth / employee / chat / department / system）
│   │   ├── middleware/       # 鉴权 / 登录限流 / 响应加固 / 头清理
│   │   ├── models/           # 数据模型
│   │   ├── services/         # 业务服务（密码哈希等）
│   │   └── utils/            # JWT / 统一响应等工具
│   ├── sql/init.sql          # 建表与种子数据（首次启动自动执行，幂等）
│   ├── .env.example          # 环境变量模板（复制为 .env 使用）
│   ├── uploads/              # 上传文件存储目录（运行期生成）
│   └── logs/                 # 运行日志目录（运行期生成）
├── frontend/                 # SvelteKit 5 前端
│   ├── src/routes/           # 页面路由（login / chat / employees / logs / profile / settings 等）
│   ├── src/lib/              # api / stores / components / types / icons / styles
│   ├── svelte.config.js      # adapter-static（fallback index.html，纯 SPA）
│   └── vite.config.ts        # 开发代理 /api、/uploads → 后端
├── sql/                      # 数据库脚本目录（目前为空，权威脚本为 backend/sql/init.sql）
└── docs/                     # 项目文档（入口：docs/README.md）
```

## 快速上手

### 前置要求

- Rust 工具链（stable，2021 edition）
- Node.js 与 npm
- MySQL 8

### 1. 启动后端

```bash
cd backend
cp .env.example .env   # 编辑 .env，至少配置 DATABASE_URL（MySQL 连接串）
cargo run
```

- 首次启动会自动执行 `backend/sql/init.sql` 建表与种子数据（幂等，可重复执行）；
- 服务默认监听 `127.0.0.1:8080`（由 `SERVER_HOST` / `SERVER_PORT` 控制）；
- 其余可选配置（`JWT_SECRET`、`BCRYPT_COST`、`TOKEN_EXPIRE_MINUTES`、`REFRESH_TOKEN_EXPIRE_DAYS`、`LOG_LEVEL`、`UPLOAD_DIR`、`CORS_ALLOWED_ORIGINS`、`COOKIE_SECURE` 等）见 `backend/.env.example` 与[根 README](../README.md)。

### 2. 启动前端

```bash
cd frontend
npm install
npm run dev
```

- 开发服务器默认运行在 `http://127.0.0.1:5173`；
- 开发模式下 Vite 将 `/api` 与 `/uploads` 代理到 `http://localhost:8080`；
- 打开首页后，通过「注册」（注册开关开启时）创建**首个管理员**账号并登录。

### 3. 生产构建

```bash
cd frontend
npm run build   # 使用 adapter-static 输出静态站点（build/）
```

静态产物由 Nginx 托管，`/api` 与 `/uploads` 反向代理到后端，详见[架构设计](架构设计.md)的生产部署形态章节。

## 首个管理员

**首个管理员**指全新部署（`employees` 表为空）时通过匿名注册接口（`POST /api/auth/register`）创建的第一个账号。系统注册开关 `registration_open` 默认开启，注册成功后自动为该账号授予全部权限码，并将 `registration_open` 置为关闭；此后注册一律返回 403。详情见[权限系统设计](权限系统设计.md)。
