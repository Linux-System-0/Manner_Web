# Manner_Web 前端开发指南

> 面向前端开发者的开发指南。内容基于当前代码库实测（`frontend/src`、`frontend/package.json`、
> `frontend/svelte.config.js`、`frontend/vite.config.ts`），与代码不一致时以代码为准。
> 后端接口细节见 [API文档.md](./API文档.md)，权限模型见 [权限系统设计.md](./权限系统设计.md)，
> 前端编码规范见 [前端-SvelteKit-重构规范.md](./前端-SvelteKit-重构规范.md)。

## 1. 技术栈

- **框架**：SvelteKit 5（`@sveltejs/kit ^2.70`）+ Svelte 5（`svelte ^5.56`，runes 语法）
- **构建**：Vite 8（`vite ^8.2`）+ TypeScript 5（`typescript ^5.6`，`strict: true`）
- **部署形态**：`@sveltejs/adapter-static ^3` 纯 SPA（`fallback: 'index.html'`；`src/routes/+layout.ts` 中 `ssr = false`、`prerender = false`），构建产物由 Nginx 托管（`try_files` 回退 index.html，模板见 [nginx-prod.conf.example](./nginx-prod.conf.example)）
- **组件**：全部自研于 `src/lib/components/`（40+ 个），**无 antd / React 运行时依赖**；样式类名沿用 antd 约定、设计令牌见 `src/styles/global.css`
- **依赖**：`package.json` 中全部为 devDependencies，**无任何运行时依赖**（npm/Node 仅构建期需要）

## 3. 开发命令

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 启动开发服务器（`vite dev`，绑定 `127.0.0.1:5173`，strictPort，仅允许回环地址；`/api`、`/uploads` 代理到 `http://localhost:8080`；需后端已启动） |
| `npm run build` | 构建静态产物（`vite build`，adapter-static 输出到 `build/`） |
| `npm run check` | `svelte-kit sync && svelte-check --tsconfig ./tsconfig.json`，TS 严格类型检查（**提交前必须通过**） |
| `npm run preview` | 本地预览构建产物（`vite preview`） |

## 4. 页面路由清单

共 9 个页面路由（纯 SPA，全部在浏览器端渲染）：

| 路由 | 页面 | 说明 | 权限要求 |
| --- | --- | --- | --- |
| `/` | 仪表盘 | 首页，登录后可见 | 登录即可 |
| `/login` | 登录 | 三步登录：用户名 → `precheck` → 密码 /（首登）设置新密码；`registration_open` 时进入注册模式 | 匿名 |
| `/chat` | 聊天 | 单聊/群聊、文本/文件消息、拉黑、群管理 | 登录即可 |
| `/employees` | 员工列表 | 分页/搜索/权限分配/防拉黑保护 | `employee:list` |
| `/employees/new` | 新增员工 | 新增员工表单 | `employee:create` |
| `/employees/[id]/edit` | 编辑员工 | 编辑员工信息与权限 | `employee:edit` |
| `/logs` | 应用日志 | 查看后端滚动日志 | `system:settings` |
| `/profile` | 个人资料 | 头像上传、个人信息、修改密码 | 登录即可 |
| `/settings` | 系统设置 | 登录页/上传限制/登录限流等 | `system:settings` |

侧边菜单（`src/lib/components/Layout.svelte` 的 `menuItems`，`$derived` 计算）按权限码动态渲染：

- 仪表盘、聊天：始终显示；
- 员工管理：`authStore.hasPermission('employee:list')` 控制；
- 应用日志、系统设置：`authStore.hasPermission('system:settings')` 控制；
- 用户菜单（`userMenuItems`）：个人资料 / 个人设置 / 退出登录。

根布局 `src/routes/+layout.svelte` 负责：`authStore.restoreLocal()` 恢复本地会话 → `preferencesStore.initialize()` 初始化偏好 → 登录页（`/login`）裸渲染，其余页面无有效会话时 `goto('/login', { replaceState: true })` 并包裹 `Layout`。

## 5. API 客户端使用

统一入口 `src/lib/api/client.ts`，导出 `client` 与错误提取函数：

```ts
import { client } from '@/lib/api/client'
import { message } from '@/lib/components/message'
import type { PaginatedData, LoginResponseData, Employee } from '@/types'

// 查询：params 自动拼到 URL，空值跳过
const res = await client.get<PaginatedData<Employee>>('/employees', { page: 1, page_size: 20 })
if (res.code !== 0) {
  message.error(res.message || '加载员工列表失败')
  return
}
const items = res.data.items

// JSON 请求体（自动设置 Content-Type: application/json）
const loginRes = await client.post<LoginResponseData>('/auth/login', { username, password })

// 更新 / 删除
await client.put<null>('/employees/123', data)
await client.delete<null>('/employees/123')

// 上传（multipart/form-data，字段名 file）
const formData = new FormData()
formData.append('file', file)
const uploadRes = await client.upload<string>('/upload', formData)
```

要点：

- **自动补全前缀**：url 不带头时自动加 `/api`；已带 `/api` 或完整 http(s) URL 则原样保留。
- **Cookie 会话**：`credentials: 'include'` 自动携带 HttpOnly Cookie（`manner_token` / `manner_refresh`），前端不持有 JWT，不手工附加 Authorization。
- **30s 超时**：AbortController 实现，超时视为网络失败（抛异常）。
- **401 自动刷新**：业务接口返回 401 时静默调用 `/auth/refresh` 换新会话；并发多个 401 只触发一次刷新（共享同一 Promise），刷新成功后重放原请求；刷新失败才清空登录态并整页跳转 `/login`。认证端点白名单 `AUTH_ENDPOINTS`（`/auth/login`、`/auth/first-login`、`/auth/refresh`）与请求级 `skipAuthRedirect: true` 会跳过该流程（如登录页拉取偏好）。
- **统一响应**：所有接口返回 `ApiResponse<T> = { code, message, data }`，成功判断 `code === 0`；业务失败按 `code !== 0` 分支处理，网络异常走 `catch`。
- **错误处理**：业务失败（`code !== 0`）直接用 `res.message` 提示；网络异常（`catch` 分支）用 `getApiError(err, fallback)` / `extractApiError(err, fallback)` 提取后端 `message`，取不到时用兜底文案。

业务模块封装模式（页面/组件不直接 `fetch`，统一走 `lib/api/*.ts` 的类型化函数）：

```ts
// src/lib/api/employees.ts —— 每业务域一个模块文件，导出类型化 async function
export async function getEmployees(
  params: EmployeeQueryParams = {},
): Promise<PaginatedResponse<Employee>> {
  return client.get<PaginatedData<Employee>>('/employees', params)
}
```

## 6. 状态管理

### authStore（`src/lib/stores/auth.ts`）

唯一认证态来源，Svelte store 形态：

- 状态：`user`（User | null）、`permissions`（string[]）、`isAuthenticated`（boolean）。
- **持久化**：localStorage 键 `manner-auth-storage` **仅存 user**（格式兼容 zustand persist 产物）；`permissions` 不落盘，刷新后由根布局经 `/auth/me`（`getMe()`）从服务端拉取覆盖，杜绝篡改本地权限。
- 方法：`setAuth(user)`（登录/首登成功）、`setUser(user)`（续期/getMe 同步）、`logout()`、`hasPermission(code)`、`restoreLocal()`（启动时从本地恢复，仅 user）。

```ts
import { authStore } from '@/lib/stores/auth'

// 组件内自动订阅
let userName = $derived($authStore.user?.name ?? '')
// 权限判断
if (authStore.hasPermission('employee:list')) { /* ... */ }
```

### preferencesStore（`src/lib/stores/preferences.ts`）

个人偏好（主题/时区/新会话位置），本地与服务端双写：

- 字段：`theme`（light/dark/system）、`timezoneMode`（system/manual）、`timezoneOffset`（小时）、`newConvPosition`（first/last）。
- **持久化**：localStorage 键 `manner-preferences`；同时同步后端 `GET/PUT /api/auth/preferences`（`initialize()` 启动时先应用本地、再尝试拉取服务端覆盖）。
- 方法：`initialize()`、`updateTheme()`、`updateTimezoneMode()`、`updateTimezoneOffset()`、`updateNewConvPosition()`；模块级 `applyTheme(theme)`（写入 `html[data-theme]` 并同步 `color-scheme`）、`getGlobalPrefs()` / `subscribe()`（供 Chat 等非组件模块读取）。

```ts
import { preferencesStore } from '@/lib/stores/preferences'

preferencesStore.updateTheme('dark') // 写本地 + 同步后端 + applyTheme
```

## 7. 组件库

全部自研于 `src/lib/components/`（40+ 个组件），类名沿用 antd 约定（`.ant-btn`、`.ant-input`、`.ant-table` 等），样式统一使用设计令牌：

`Alert` `Avatar` `Badge` `Button` `Card` `Checkbox` `Col` `ConfirmModal` `DatePicker` `Descriptions` `Divider` `Dropdown` `Empty` `Form` `FormItem` `Input` `Layout` `Link` `List` `ListItem` `Menu` `Modal` `Pagination` `Popconfirm` `PreferencesModal` `Radio` `Result` `Row` `Select` `Space` `Spin` `Statistic` `Switch` `Table` `Tag` `Text` `Title` `Tooltip` `Tree` `TreeSelect` `Typography` `Upload`

- **命令式能力**：`message.ts`（`message.success/error/warning/info`，轻量 toast）与 `modal.ts`（命令式确认框），不在页面里各自造轮子。
- **图标**：`src/lib/icons/`，`Icon.svelte` + `icon-data.ts`（内联 SVG 数据），通过 `icon` 名引用（如 `icon="team"`、`icon="message"`）。

## 8. 样式

- **设计令牌**：`src/styles/global.css` 定义 `--ant-color-primary`（#1677ff）、`--ant-color-primary-hover`、`--ant-color-success`、`--ant-color-warning`、`--ant-color-error`、`--ant-color-text`、`--ant-color-bg-container`、`--ant-border-radius`、`--ant-box-shadow`、`--ant-font-size` 等，对齐 antd 5 token 命名；另有布局/组件专用变量（`--ant-layout-sider-bg`、`--ant-menu-dark-*`、`--ant-card-bg`、`--chat-*` 等）。
- **主题**：`html[data-theme="light" | "dark"]` 切换明暗（dark 下同时设置 `color-scheme: dark`）；由 `preferencesStore.applyTheme()` 驱动。
- **规范**：新样式一律使用设计令牌，禁止写死色值；组件内 `<style>` 只放布局性样式，主题相关样式放到 `global.css` 的令牌层。

## 9. 新增页面 / 组件的步骤

### 新增页面（如「统计报表」`/reports`）

1. 新建路由文件：`src/routes/reports/+page.svelte`（`<script lang="ts">` + Svelte 5 runes）。
2. 数据加载：`onMount` 中调用 `lib/api` 模块函数，用 `$state` 保存数据、`$derived` 派生展示值；加载中渲染 `Spin`，空态渲染 `Empty`。
3. 复用组件：从 `$lib/components` 引入；页面内容区由 `Layout` 已包裹，无需重复搭框架。
4. 类型与接口：新增接口类型定义到 `src/lib/types/index.ts`；在 `src/lib/api/` 新增对应业务模块文件（如 `reports.ts`）导出类型化函数，页面不直接 `fetch`。
5. 权限：受权限控制的页面在 `src/lib/components/Layout.svelte` 的 `menuItems` 中按权限码加入菜单项（如 `authStore.hasPermission('employee:list')`；新权限码需先在 `backend/sql/init.sql` 与后端确认存在，勿自行发明）。
6. 验证：`npm run check` 必须通过；`npm run dev` 联调后端接口；`npm run build` 确认可构建。

### 新增组件（如 `AvatarList.svelte`）

1. 在 `src/lib/components/AvatarList.svelte` 创建组件，Props 用 `$props()` 声明（含默认值），交互回调用 `onClick` 等 `onXxx` 命名 prop 传入。
2. 根元素类名沿用 antd 约定（如 `ant-avatar-list`），样式使用设计令牌。
3. 被多处使用时从 `$lib/components` 统一引入；组件只做展示与交互，不发请求。
4. `npm run check` 验证类型。
